# Fine-Timing: adapting faithfulness metrics to historians' reading of time

Code and data to reproduce the experiments of the paper: fine-tuning two NLI-based faithfulness metrics
(`mDeBERTa-v3-base` and `MiniCheck-RoBERTa-Large`) on rewrites of temporal expressions labelled with a historian-defined
criterion, and evaluating them against a historian's judgements, zero-shot NLI baselines and LLM judges.

## Layout

```
run_pipeline.py      end-to-end driver
configs/             data_en.yaml, data_fr.yaml, training.yaml
data/
  rag_outputs/       RAG summaries and retrieved chunks of the three English journals (dhq, dm, chdj)
  anchors/           dated expressions of the summaries with their annotation (dhq, dm, chdj, fr)
  rewrites/          rewrites generated by Mistral-Small-24B (en, fr) and the hand-labelled silver rewrites (en_silver)
  expert_set.json    the historian's expert set, in French and English
  reference/         cached probabilities of the reported checkpoints
tempolib/            library: temporal-expression extraction, the criterion (judge), prompts, metrics
pipeline/            dataset construction and training      (python -m pipeline.<step>)
analysis/            evaluation, tables and statistics      (python -m analysis.<script>)
results/             outputs of the analysis scripts
outputs/             written by the pipeline (git-ignored): splits, datasets, checkpoints
```

## Installation

Python >= 3.10 (tested with 3.12): `pip install -r requirements.txt`. All commands run from the repository root.
A GPU is needed to fine-tune, to rescore with local checkpoints, to re-extract the anchors and for the retention tests.
Models and public datasets are downloaded from the Hugging Face Hub on first use.

## Reproducing the paper

```bash
python run_pipeline.py            # default stages (about 10 minutes on CPU): splits, datasets, evaluate, tables
python run_pipeline.py --list     # all stages
python run_pipeline.py --dry-run --all   # every command, in order
```

The default run rebuilds the training sets from the shipped anchors and rewrites, scores the models with the cached
probabilities of the reported checkpoints and the cached LLM verdicts, and regenerates the tables of `results/`.
Finished steps are skipped (`--force` reruns them). Optional stages are added with `--with <stage>`.

| Paper | Stage | What it does | Output |
|---|---|---|---|
| Sect. 3.1, 4.1 | `anchors` (GPU) | extracts the dated expressions of the RAG summaries and aligns them with a source sentence (bge-m3) | `outputs/anchors/` |
| Sect. 4.1 | `splits` | splits the annotated anchors by source article into train / dev / test | `outputs/splits/` |
| Sect. 4.2 | `generate` (LLM server) | four rewrites of each anchor's temporal expression, one per transformation type, valid or invalid | `outputs/rewrites/` |
| Sect. 4.2 | `datasets` | labels the rewrites with the criterion, adds the silver labels, builds the training sets (main, criterion labels only, generator labels, with MNLI, French) | `outputs/datasets/` |
| Sect. 4.4 | `train` (GPU) | fine-tunes the ten runs of `configs/training.yaml` | `outputs/models/` |
| Sect. 4.4, 5 | `evaluate` | scores the models and the LLM judges on the expert set | `results/probabilities/`, `results/llm_judge/` |
| Tables 2, 4, 5, Sect. 4.1–4.2, 6.1 | `tables` | Table 5; data statistics; rewrites misclassified by all four NLI-based checkers | `results/tables/table5.md`, `results/statistics/` |
| Table 3 | `illustration` | verdicts of the criterion, mDeBERTa, MiniCheck and Qwen3-30B-A3B on seven rewrites of 1294 | `results/tables/table3.md` |
| Sect. 6.2 | `retention` (GPU) | MNLI-m, SNLI, Reveal and FactCheck-GPT before and after fine-tuning | `results/retention/` |


### Rewrites

The shipped rewrites were generated with `mistralai/Mistral-Small-24B-Instruct-2501` served by vLLM (temperature 0.7,
seed 13). Generation is not bit-reproducible across hardware, hence the shipped files. To regenerate them with any
OpenAI-compatible server (edit `llm:` in `configs/data_*.yaml`) and rebuild the datasets from them:

```bash
python run_pipeline.py --stages generate
python run_pipeline.py --stages splits,datasets --own-rewrites
```

### Training

Every run uses learning rate 2e-5, 10 epochs, effective batch size 16, inputs up to 512 tokens, AdamW, warm-up 6 %,
weight decay 0.01, seed 42 and fp32, and keeps the epoch with the best dev accuracy (`configs/training.yaml`). Runs:
`{mdeberta,roberta}_{main,rule_only,generator_only,mnli}`, `mdeberta_fr` and `mdeberta_fr_from_en` (English model
trained further on the French data). The checkpoints are not distributed: `analysis.score_models` uses the local
checkpoint (`outputs/models/<run>` or `$MODELS_DIR/<run>`) when it exists, and the cached probabilities of
`data/reference/` otherwise.

### LLM judges

The judges (Qwen3-4B-Instruct-2507 and Qwen3-30B-A3B-Instruct-2507, rules prompt in `analysis/llm_judge.py`) are
queried through an OpenAI-compatible server (`--llm-base-url`, default `http://localhost:1234/v1`, temperature 0). Their
verdicts are cached in `results/llm_judge/`, so the tables are regenerated without a server. LLM outputs are not
deterministic: a new run can differ slightly from the cached one.

## Data

**Anchors** (`data/anchors/*.csv.gz`): one row per dated expression of a RAG summary sentence.

| Column | Meaning |
|---|---|
| `item_id`, `doc_id` | anchor id; summary id |
| `sentence`, `expression` | summary sentence and the dated expression it contains |
| `source_window`, `source_chunk`, `source_file`, `source_pub_year` | aligned source sentence, retrieved chunk, file and publication year |
| `annotation` | type of the transformation: `none` (reformulation), `generalization`, `precision`, `wrong_date`; empty = undecided |
| `validity` | for generalizations and precisions: `valid` or `invalid` |
| `suggested_*` | suggestion from the aligned source (interval relation) |

**Rewrites** (`data/rewrites/*.jsonl.gz`): anchor, original sentence, source `document`, requested `error_type`, `polarity`
(`valid` / `invalid`), the rewritten `claim` and generation metadata. `en_silver.jsonl.gz` has the same columns plus
`label_manual`, the hand-checked label of the silver rewrites.

**Dataset rows** (`outputs/datasets/*/{train,dev}.jsonl`): `document`, `claim`, `label` (1 = faithful), `error_type`,
`granularity`, `anchor_expression`, `original_sentence`, `doc_id`, `origin` (`human`: the annotated summary sentences
themselves; `synthetic`: the labelled rewrites; `silver`: the hand-labelled rewrites; `mnli`: the MNLI pairs of Sect. 6.2).

**Expert set** (`data/expert_set.json`): 36 short documents with several rewrites of their temporal expression, each
given in French and English with the historian's label (`true` valid, `false` invalid, `null` tolerated boundary case).
